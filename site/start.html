Step by step

From a new server to a live app

Set up an Ubuntu server, install modest-deploy, and launch a first app on your own domain.

What you need

  • A server running Ubuntu 26.04 LTS, with at least 1GB of memory. A DigitalOcean droplet or similar is fine. 24.04 LTS also works, but it can't stop a compromised product from opening other ports (why).
  • A domain you can add DNS records to: one name for each product, and one for deploys, such as deploy.example.org.
  • A GitHub account, and on your computer, Node 24 or later and, ideally, GitHub's command line tool, gh, signed in (gh auth login). Launch uses it to make the repository and connect it in one go. Without it, launch changes nothing and prints the steps to do by hand instead, with your product's own command to run.

1. Set up the server

You do this once. When you create the server, add your SSH key. Then sign in as root and make a user of your own, with your key. Put your own name in place of yourname, here and below.

terminal
$ adduser yourname
$ usermod -aG sudo yourname
$ rsync --archive --chown=yourname:yourname ~/.ssh /home/yourname

Sign in again as that user (ssh yourname@your-server) before going on. Then turn off signing in by password, and as root:

/etc/ssh/sshd_config.d/10-local.conf
PasswordAuthentication no
KbdInteractiveAuthentication no
PermitRootLogin no
terminal
$ sudo systemctl reload ssh

Add a firewall that lets in only SSH, HTTP, and HTTPS. Your provider's control panel usually has one; on DigitalOcean it's under Networking, then Firewalls. Then install Node, Caddy, and automatic security updates:

terminal
$ curl -fsSL https://deb.nodesource.com/setup_24.x | sudo -E bash -
$ sudo apt install -y nodejs caddy unattended-upgrades

The first line adds NodeSource's package repository for Node 24. Caddy comes from Ubuntu's own packages.

2. Install modest-deploy

terminal
$ sudo npm install -g modest-deploy
$ sudo modest-deploy check

check lists what it needs, each marked ok or with what to change. When everything is ok, install it, with the name GitHub will send deploys to:

terminal
$ sudo modest-deploy install --domain deploy.example.org

Then add a DNS record pointing deploy.example.org at the server's address. Caddy gets its HTTPS certificate once the record works.

3. Set up your computer

terminal
$ npm install -g modest-deploy

Give the server a short name in your SSH settings, so ssh myserver signs you in:

~/.ssh/config
Host myserver
  HostName 203.0.113.7
  User yourname

Use your server's address and your user. launch runs modest-deploy add on the server with sudo, over SSH, where it can't ask for your password. On the server, let your user run that one command without it (signed in as that user, so $USER is your name):

terminal
$ echo "$USER ALL=(root) NOPASSWD: $(which modest-deploy) add *" | sudo tee /etc/sudoers.d/modest-deploy
$ sudo chmod 440 /etc/sudoers.d/modest-deploy && sudo visudo -c

Everything else still asks for your password.

4. Write an app

An app is a Node server, server.js, that listens on the port and address it's given. In a new folder:

server.js
import { createServer } from "node:http";

// modest-deploy gives each app its port, and 127.0.0.1 to listen on (Caddy is in front).
const port = Number(process.env.PORT ?? 3000);
const host = process.env.HOST ?? "127.0.0.1";

createServer((req, res) => {
  res.writeHead(200, { "content-type": "text/plain; charset=utf-8" });
  res.end("Hello from blog\n");
}).listen(port, host, () => console.log(`Listening on http://${host}:${port}`));
package.json
{
  "name": "blog",
  "private": true,
  "type": "module",
  "scripts": {
    "start": "node server.js"
  }
}

And a CI workflow. modest-deploy deploys when this passes on main, so put your tests here:

.github/workflows/ci.yml
name: CI

on:
  push:
    branches: [main]

permissions:
  contents: read

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-node@v7
        with:
          node-version: 24
      - run: node --check server.js

Keep anything the app writes in process.env.DATA_DIR: everything else is read-only to it. If it has dependencies, commit a package-lock.json.

5. Launch it

terminal
$ modest-deploy launch blog blog.example.org --server myserver

This makes a private blog repository on your own GitHub account (add --public for a public one), sets the app up on the server, and connects the two: from then on, the server fetches the code from GitHub whenever CI passes.

  • For an organisation, name it: --repo your-org/blog. It's made there (if you're allowed to make repositories there), or connected if it's there already. If gh is signed in to more than one GitHub account, it uses the active one (gh auth status).
  • Already have the repository on GitHub? Launch connects that one instead of making a new one, and leaves its code alone. It looks for your-username/blog; for any other, add --repo owner/name. Run it from any folder: it works with GitHub, not with the files on your computer.
  • Memory: the app gets 512M (less on a server with less to spare; launch says how much). If it's the only one on the server, add --memory max to give it everything the server can spare (more on memory).

Then:

  1. Add a DNS record pointing shop.example.org at the server.
  2. For a new repository, push the folder to it:
terminal
$ git init -b main && git add -A && git commit -m "First version"
$ git remote add origin git@github.com:YOUR-USER/blog.git
$ git push -u origin main

For one that already has your code, there's nothing to push: deploy what's on main now, from the server (-t lets sudo ask for your password):

terminal
$ ssh -t myserver sudo modest-deploy deploy blog

When CI passes (or once that deploy finishes), it's live. Open https://blog.example.org, or check on the server:

terminal
$ modest-deploy list --server myserver
$ ssh -t myserver sudo modest-deploy logs blog

From now on, each push to main that passes CI deploys the new version.

6. Keys and sign-in

An app's own keys, such as an email service's, go in its environment file on the server, one KEY=value a line:

terminal
$ sudo nano /etc/modest-deploy/env/blog.env
$ sudo modest-deploy restart blog

For sign-in, modest-auth works with it as it is: keep its database in DATA_DIR, set origin to the app's address, and name Caddy as the proxy in front with trustedProxies: ["loopback"].
